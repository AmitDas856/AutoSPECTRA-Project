# Week 2 Reporting Metadata Requirements

**Owner:** Miftha Thahniyath  
**Role:** Reporting and Metadata Lead

## Metadata Needed by Later Incident Reports

The Week 2 audit confirms that later reports should retain:

- source file;
- capture type;
- start and end timestamp;
- number of parsed messages;
- normal and injected-message counts;
- dominant CAN ID;
- number of unique CAN IDs;
- DLC distribution;
- message timing statistics;
- payload statistics.

## Flask Display Requirements

The future application should display:

- uploaded filename;
- parsing success or error;
- frame count;
- window count;
- class probabilities;
- selected prediction;
- confidence;
- incident narrative;
- downloadable results.

## Week Boundary

Week 2 defines the metadata requirements. Incident-report generation and Flask implementation are reserved for Week 8.
